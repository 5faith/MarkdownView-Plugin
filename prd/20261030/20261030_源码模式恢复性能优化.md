# 源码模式恢复性能优化

## 需求

- 源码模式修改内容后切回富文本时，减少主线程一次性解析和更新大文档造成的卡顿。
- 仅在文档结构安全且语义保持一致时采用增量或分批解析；无法安全拆分时保留完整文档解析。
- Mermaid 运行时及图表延迟到图表进入可视区域后加载和渲染；屏外节点更新后，在重新可见时渲染最新内容。
- 在开发者控制台记录富文本恢复策略、解析与应用耗时，以及 Mermaid 图表渲染耗时，便于定位性能问题。

## 实现约束

- 单个安全段落或标题的变更可直接替换对应 ProseMirror 节点。
- 多个安全 Markdown 块分批解析和提交，每批不超过 3 个块，并在批次间让出一帧。
- 引用链接等依赖全文上下文的语法，以及不支持的复杂块结构，不得分块解析，必须走完整解析以保持 Markdown 语义。
- 源码恢复期间的中间 ProseMirror 更新不得同步回 VS Code 文本文档。
- 若浏览器不支持 `IntersectionObserver`，Mermaid 图表应立即渲染，保证兼容性。

## 验收标准

- 类型检查、扩展打包和 `git diff --check` 通过。
- 单块安全编辑使用增量更新；多个安全块分批更新；无法安全拆分时完整解析。
- 分批解析期间不会将不完整内容写回 VS Code 文本文档。
- 屏外 Mermaid 图表不加载运行时；进入可视区域后加载和渲染，且源码仍可查看。
