# 预览折叠状态修复

## 1. 需求背景

只读（预览）模式下点击 `<details>/<summary>` 折叠块，点击"展开"会先展开后回折，点击"收起"会先收起后回弹——每次点击都被回退，折叠块在预览模式下形同虚设。编辑模式下无此问题。

## 2. 根因

点击 summary 时浏览器原生翻转 DOM 的 `open`，details NodeView 监听 `toggle` 事件将 `open` 写回 ProseMirror 节点 attr，触发 `markdownUpdated` → `postChange`（120ms 防抖）向宿主发送 `change` 消息。宿主侧只读模式拒绝写入（`provider.ts` `applyWebviewChange` 中 `canEdit=false` 分支），并调用 `postDocumentUpdate` 把**未修改的旧文档全文**回传；webview `applyHostUpdate` 发现内容与 `lastAppliedMarkdown` 不一致，触发 `replaceAll` 重建文档，折叠状态被回退。

此外 details NodeView 缺少 `ignoreMutation` 防护：`open` 属性翻转产生的 DOM 属性突变被 ProseMirror DOMObserver 当作内容变化处理，加重了状态振荡。

## 3. 需求内容

1. 只读模式下折叠块的展开/收起是**纯界面状态**：记在 webview 内部（DOM + ProseMirror 文档），**不向宿主发送 `change`**，文件内容不被修改。
2. 会话内保留：预览中折叠后切到编辑模式仍保持本次会话的选择；只有宿主主动推送的外部文档修改才会覆盖（外部修改优先）。
3. 编辑/源码模式的写回行为不变（可编辑模式照常同步到 `TextDocument`）。
4. details NodeView 补齐桌面版（MarkdownView 仓库）已验证的 `ignoreMutation` 防护：忽略 `open` 属性突变，交由 `toggle` 处理器统一同步。

## 4. 验收标准

1. 只读模式单击 summary 仅一次状态翻转，不回退；全程无 `change` 消息、无宿主拒绝。
2. 只读展开 → 切编辑模式状态保留；文件未被修改。
3. 编辑模式切换折叠块后写回宿主，宿主回显不引起回退，markdown 往返保留 `open` 属性。
4. 源码模式编辑写回不受影响。
5. `pnpm run check`、`pnpm run package`、`git diff --check` 通过；`pnpm run dev` 手动过三态模式。
