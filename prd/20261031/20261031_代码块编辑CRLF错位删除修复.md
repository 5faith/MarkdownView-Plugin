# 代码块编辑 CRLF 错位删除修复

## 需求

用户报告：编辑模式代码块中，鼠标（光标）在第 7 行（空行）按退格，被删除的却是代码中另一处的字符 `l`（如 `Hello` / `world` 中的 l），删除位置与光标位置错位。

## 根因（已用浏览器 harness 复现实锤）

- 仓库 `examples/local-test.md` 在 Windows 检出后为 CRLF 行尾（`git ls-files --eol`：`i/lf w/crlf`，`core.autocrlf=true`），宿主经 `getText()` 传入 Webview 的 markdown 含 `\r\n`。
- Milkdown/remark 解析时正文段落被归一为 `\n`，但 **代码块文本节点把 `\r` 当普通字符保留**（回写 markdown 中代码围栏内为 `\r\n` 可证）。
- Crepe 代码块 NodeView（`@milkdown/components` CodeMirrorBlock）中 CodeMirror 将 `\r\n` 折叠为单个换行，其 `forwardUpdate` 以 **1:1 偏移映射**（`offset + cmOffset`）把 CM 偏移换算为 ProseMirror 偏移。CM 视角每行少 1 个字符，导致每个编辑位置向左漂移 N（N = 编辑点之前的 CRLF 行数）。
- 因此在代码块内退格删除换行符时，实际删除落在左边第 N 个字符上——正好是 `Hello` / `world` 中的 `l`。只读模式不走该映射，故只读正常、编辑必坏。
- harness 复现（修复前）：CRLF 文档 + 代码块内 Enter→退格，`fmt.Println("Hello, 世界")` 被拆行、内容错位，回写 markdown 同步损坏。

## 方案

在 Webview 边界统一行尾（`src/webview/main.ts`）：

1. **入口归一化**：`applyHostUpdate` 收到宿主 markdown 后先 `normalizeMarkdownEol`（`\r\n`/`\r` → `\n`）再进入 Milkdown，保证 CM↔PM 偏移映射恒为 1:1；同时记录 `hostUsesCrLf`（原文档是否 CRLF）。
2. **出口还原**：`postChange` 回写 VS Code 时按 `hostUsesCrLf` 将 `\n` 还原为 `\r\n`，保持用户文件行尾不变，避免整文件 EOL 翻转与回环抖动。

内部（PM 文档、源码模式 textarea、增量恢复、Mermaid 源码面板）全部以 LF 运作。

## 验收标准

- CRLF 文档：代码块内 Enter/退格/点击后光标处编辑准确无误，不再错位删除；回写 markdown 代码块内容与编辑器内容一致。
- 回写保持原文档 CRLF 行尾；LF 文档回写仍为 LF。
- LF 文档回归：编辑行为与修复前一致（1:1 映射）。
- `pnpm run check`、`pnpm run package`、`git diff --check` 通过。
