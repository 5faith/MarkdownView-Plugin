# 代码块编辑CRLF错位删除修复

## 需求说明

## 需求

用户报告：编辑模式代码块中，鼠标（光标）在第 7 行（空行）按退格，被删除的却是代码中另一处的字符 `l`（如 `Hello` / `world` 中的 l），删除位置与光标位置错位。

## 根因（已用浏览器 harness 复现实锤）

- 仓库 `examples/local-test.md` 在 Windows 检出后为 CRLF 行尾（`git ls-files --eol`：`i/lf w/crlf`，`core.autocrlf=true`），宿主经 `getText()` 传入 Webview 的 markdown 含 `\r\n`。
- Milkdown/remark 解析时正文段落被归一为 `\n`，但 **代码块文本节点把 `\r` 当普通字符保留**（回写 markdown 中代码围栏内为 `\r\n` 可证）。
- Crepe 代码块 NodeView（`@milkdown/components` CodeMirrorBlock）中 CodeMirror 将 `\r\n` 折叠为单个换行，其 `forwardUpdate` 以 **1:1 偏移映射**（`offset + cmOffset`）把 CM 偏移换算为 ProseMirror 偏移。CM 视角每行少 1 个字符，导致每个编辑位置向左漂移 N（N = 编辑点之前的 CRLF 行数）。
- 因此在代码块内退格删除换行符时，实际删除落在左边第 N 个字符上——正好是 `Hello` / `world` 中的 `l`。只读模式不走该映射，故只读正常、编辑必坏。
- harness 复现（修复前）：CRLF 文档 + 代码块内 Enter→退格，`fmt.Println("Hello, 世界")` 被拆行、内容错位，回写 markdown 同步损坏。

## 方案

在 Webview 边界统一行尾（`src/webview/main.ts`）：

1. **入口归一化**：`applyHostUpdate` 收到宿主 markdown 后先 `normalizeMarkdownEol`（`\r\n`/`\r` → `\n`）再进入 Milkdown，保证 CM↔PM 偏移映射恒为 1:1；同时记录 `hostUsesCrLf`（原文档是否 CRLF）。
2. **出口还原**：`postChange` 回写 VS Code 时按 `hostUsesCrLf` 将 `\n` 还原为 `\r\n`，保持用户文件行尾不变，避免整文件 EOL 翻转与回环抖动。

内部（PM 文档、源码模式 textarea、增量恢复、Mermaid 源码面板）全部以 LF 运作。

## 验收标准

- CRLF 文档：代码块内 Enter/退格/点击后光标处编辑准确无误，不再错位删除；回写 markdown 代码块内容与编辑器内容一致。
- 回写保持原文档 CRLF 行尾；LF 文档回写仍为 LF。
- LF 文档回归：编辑行为与修复前一致（1:1 映射）。
- `pnpm run check`、`pnpm run package`、`git diff --check` 通过。

## 修改记录

## 问题

# 编辑模式图片与链接修改

## 需求说明

## 需求

编辑模式（WYSIWYG）下提供修改已插入图片与链接的入口。现状：点击链接直接跳转、无法改 href；Crepe ImageViewer 只有题注与缩放、无法改图片 src。

## 方案

- 链接：编辑模式点击链接 → 弹出浮动操作条（当前 href + 编辑/打开/移除）；编辑复用 `requestValue` 对话框预填当前 href，确认后按 `<a>` 元素定位 mark 范围执行 `removeMark + addMark`；Ctrl/Cmd+Click 或只读模式保持直接打开（复用 `openLink` 流程）。
- 图片：编辑模式点击 `image-block` 或行内图片 → 操作条显示原始 src + 更换地址；确认后经 `posAtDOM` 定位节点（`image` / `image-block` 类型，读取 PM 属性而非被 `proxyDomURL` 改写过的 DOM src）执行 `setNodeMarkup`。
- URL 校验：相对路径（含 `#anchor`）放行；链接另允许 `mailto:`，图片另允许 `data:image/*`；http/https 校验 host，拒绝 localhost、环回、私有/保留地址段（10/8、172.16-31、192.168/16、169.254/16、fc00::/7、0.0.0.0、.local）及其他 scheme（含 `javascript:`）；非法输入在对话框 label 显示错误且不应用（`requestValue` 增加可选校验回调，校验失败 `preventDefault` 保持对话框打开）。
- 配套：provider `applyWebviewChange` 成功后追加 `postDocumentUpdate`，回传重算的 images 映射；webview 在 `latestMarkdown === lastAppliedMarkdown` 的跳过路径调用 `refreshProxiedImageSources()`，把文档内相对路径图片的 DOM src 直接改为新映射 URI（Crepe 图片视图仅在渲染时读 `proxyDomURL`，否则改相对路径后一直破图）。
- 不启用 Crepe `LinkTooltip`：其确认流程 `sanitizeLinkHref` 会清空相对路径 href，且覆写 `ToggleLink` 命令键影响现有工具栏。

## 验收标准

- 编辑模式点击链接/图片出现操作条且不发生跳转；编辑/移除/打开/Ctrl+Click/只读行为符合预期。
- 修改 href / src 后回写 markdown 正确；改相对路径图片后显示立即刷新。
- 非法地址（环回/私有 host、`javascript:`）被拒绝并在对话框提示；合法相对路径与 mailto 通过。
- LF 与 CRLF 文档均正常（沿用 CRLF 归一化基线，回写保持原行尾）。
- `pnpm run check`、`pnpm run package`、`git diff --check` 通过。

## 2026-10-31 — 点击拦截提升到 document 捕获阶段

# 编辑模式图表渲染修复与重构

## 需求说明

## 问题

只读模式图表渲染正常，编辑模式总是渲染异常：图表报 “Syntax error in text / No diagram type detected”、预览丢失、且坏源码被写回 VS Code 文档。

## 根因（已在 prosemirror-view 源码中定位）

Mermaid NodeView 在内部自管 DOM（`preview.innerHTML = svg`、占位/错误状态条写入），但未实现 `ignoreMutation`。prosemirror-view 的 `DOMObserver.flush()` 仅在 `view.editable`（编辑模式）处理 DOM 变更；`registerMutation` 对 childList 变更且目标不在 `contentDOM` 内时返回整个节点范围，ProseMirror 据此用 schema 解析器重读该段 DOM——SVG 注入被误当作文档内容，mermaid 节点源码被清空/错位（复现：编辑模式输入后 34 个图表源码全部损坏，源码在相邻节点间错位），随后渲染失败且损坏 markdown 经 `markdownUpdated` 写回文档。只读模式不处理 DOM 变更，因此不受影响。

## 需求

- NodeView 实现 `ignoreMutation`：`contentDOM` 之外的内部 DOM 变更一律告知 ProseMirror 忽略；`contentDOM` 内的编辑（用户输入）仍正常处理。
- 源码面板不再用 `<details>` 原生收起（`display:none` 隐藏可编辑 contentDOM 属已知风险）：保持外观（“▸ Mermaid 源码”行）与交互不变，折叠改由内层 wrapper 的 `visibility:hidden; height:0` 实现，contentDOM 始终存在于 DOM 与布局树。
- 结构重构：渲染队列/缓存/可视区调度与 Mermaid NodeView 从 markdown-extensions.ts 拆分至独立的 mermaid-view.ts，职责清晰（schema/remark 转换 vs 图表视图）。
- 既有行为全部保持：编辑模式即时预览、默认收起源码、空源码自动展开、编辑 800ms/外部 250ms 防抖、渲染失败保留旧图 + 状态条、可视区懒加载、主题+源码 LRU 缓存。
