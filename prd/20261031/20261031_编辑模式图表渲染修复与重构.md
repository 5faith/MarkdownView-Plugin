# 编辑模式图表渲染修复与 NodeView 重构

## 问题

只读模式图表渲染正常，编辑模式总是渲染异常：图表报 “Syntax error in text / No diagram type detected”、预览丢失、且坏源码被写回 VS Code 文档。

## 根因（已在 prosemirror-view 源码中定位）

Mermaid NodeView 在内部自管 DOM（`preview.innerHTML = svg`、占位/错误状态条写入），但未实现 `ignoreMutation`。prosemirror-view 的 `DOMObserver.flush()` 仅在 `view.editable`（编辑模式）处理 DOM 变更；`registerMutation` 对 childList 变更且目标不在 `contentDOM` 内时返回整个节点范围，ProseMirror 据此用 schema 解析器重读该段 DOM——SVG 注入被误当作文档内容，mermaid 节点源码被清空/错位（复现：编辑模式输入后 34 个图表源码全部损坏，源码在相邻节点间错位），随后渲染失败且损坏 markdown 经 `markdownUpdated` 写回文档。只读模式不处理 DOM 变更，因此不受影响。

## 需求

- NodeView 实现 `ignoreMutation`：`contentDOM` 之外的内部 DOM 变更一律告知 ProseMirror 忽略；`contentDOM` 内的编辑（用户输入）仍正常处理。
- 源码面板不再用 `<details>` 原生收起（`display:none` 隐藏可编辑 contentDOM 属已知风险）：保持外观（“▸ Mermaid 源码”行）与交互不变，折叠改由内层 wrapper 的 `visibility:hidden; height:0` 实现，contentDOM 始终存在于 DOM 与布局树。
- 结构重构：渲染队列/缓存/可视区调度与 Mermaid NodeView 从 markdown-extensions.ts 拆分至独立的 mermaid-view.ts，职责清晰（schema/remark 转换 vs 图表视图）。
- 既有行为全部保持：编辑模式即时预览、默认收起源码、空源码自动展开、编辑 800ms/外部 250ms 防抖、渲染失败保留旧图 + 状态条、可视区懒加载、主题+源码 LRU 缓存。

## 验收标准

- 浏览器 harness（真实 webview bundle + acquireVsCodeApi shim）回归：只读渲染正常；编辑模式输入文字、滚动渲染、编辑图表源码后，全部图表源码不被破坏（唯一差异为用户主动编辑）；预览实时更新且正确回写文档；模式往返后源码与预览保持。
- `pnpm run check`、`pnpm run package` 和 `git diff --check` 通过。
