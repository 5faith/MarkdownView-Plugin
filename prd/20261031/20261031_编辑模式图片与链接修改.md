# 编辑模式图片与链接修改

## 需求

编辑模式（WYSIWYG）下提供修改已插入图片与链接的入口。现状：点击链接直接跳转、无法改 href；Crepe ImageViewer 只有题注与缩放、无法改图片 src。

## 方案

- 链接：编辑模式点击链接 → 弹出浮动操作条（当前 href + 编辑/打开/移除）；编辑复用 `requestValue` 对话框预填当前 href，确认后按 `<a>` 元素定位 mark 范围执行 `removeMark + addMark`；Ctrl/Cmd+Click 或只读模式保持直接打开（复用 `openLink` 流程）。
- 图片：编辑模式点击 `image-block` 或行内图片 → 操作条显示原始 src + 更换地址；确认后经 `posAtDOM` 定位节点（`image` / `image-block` 类型，读取 PM 属性而非被 `proxyDomURL` 改写过的 DOM src）执行 `setNodeMarkup`。
- URL 校验：相对路径（含 `#anchor`）放行；链接另允许 `mailto:`，图片另允许 `data:image/*`；http/https 校验 host，拒绝 localhost、环回、私有/保留地址段（10/8、172.16-31、192.168/16、169.254/16、fc00::/7、0.0.0.0、.local）及其他 scheme（含 `javascript:`）；非法输入在对话框 label 显示错误且不应用（`requestValue` 增加可选校验回调，校验失败 `preventDefault` 保持对话框打开）。
- 配套：provider `applyWebviewChange` 成功后追加 `postDocumentUpdate`，回传重算的 images 映射；webview 在 `latestMarkdown === lastAppliedMarkdown` 的跳过路径调用 `refreshProxiedImageSources()`，把文档内相对路径图片的 DOM src 直接改为新映射 URI（Crepe 图片视图仅在渲染时读 `proxyDomURL`，否则改相对路径后一直破图）。
- 不启用 Crepe `LinkTooltip`：其确认流程 `sanitizeLinkHref` 会清空相对路径 href，且覆写 `ToggleLink` 命令键影响现有工具栏。

## 验收标准

- 编辑模式点击链接/图片出现操作条且不发生跳转；编辑/移除/打开/Ctrl+Click/只读行为符合预期。
- 修改 href / src 后回写 markdown 正确；改相对路径图片后显示立即刷新。
- 非法地址（环回/私有 host、`javascript:`）被拒绝并在对话框提示；合法相对路径与 mailto 通过。
- LF 与 CRLF 文档均正常（沿用 CRLF 归一化基线，回写保持原行尾）。
- `pnpm run check`、`pnpm run package`、`git diff --check` 通过。
